## 2. In-Depth Subsystem Audit

### 2.1 Storage Layout & Data Structure Architecture

`ObjectPool<T>` utilizes a dual-layer index management architecture combining JavaScript reference mapping with native C-style typed-array buffers:

| Structure | Type | Size | Purpose | Complexity |
| :--- | :--- | :--- | :--- | :--- |
| `storage` | `T[]` | `capacity` | Contiguous object reference buffer | $O(1)$ access |
| `freeIndices` | `Int32Array` | `capacity` | LIFO stack of available storage slot indices | $O(1)$ push/pop |
| `activeIndices` | `Int32Array` | `capacity` | Dense packed array of currently active object indices | $O(1)$ swap-and-pop |
| `itemToActiveSlot`| `Int32Array` | `capacity` | Reverse lookup mapping storage index $\to$ slot in `activeIndices` | $O(1)$ slot lookup |
| `activeFlags` | `Uint8Array` | `capacity` | 1-byte binary flag per item (`1` = active, `0` = free) | $O(1)$ state verification |
| `itemToIndexMap` | `Map<T, number>` | `capacity` | Identity hash map from object reference $\to$ storage index | $O(1)$ amortized lookup |

#### Zero-GC Steady-State Proof
- `new Array<T>(capacity)` and all typed arrays are allocated strictly once inside `constructor(options)`.
- During active gameplay, `acquire()`, `release()`, `forEachActive()`, and `isActive()` execute without invoking `new`, `Array.prototype.push`, `Array.prototype.splice`, `Array.prototype.slice`, or creating transient closures.
- Frame GC pressure generated by the pool subsystem during active gameplay is **0 bytes/frame**.

### 2.2 Mechanics Verification & Invariant Proofs

#### A. Acquire Mechanics ($O(1)$)
```ts
public acquire(): T | null {
  if (this.freeHead <= 0) {
    return null; // Exhaustion guard
  }

  const itemIndex = this.freeIndices[--this.freeHead]; // LIFO pop
  const slot = this._activeCount++;

  this.activeIndices[slot] = itemIndex;                // Dense append
  this.itemToActiveSlot[itemIndex] = slot;             // Reverse index update
  this.activeFlags[itemIndex] = 1;                     // Active flag set

  const item = this.storage[itemIndex];
  if (this.acquireCallback) {
    this.acquireCallback(item);
  }
  return item;
}
```
- **Execution Invariant**: If `freeHead > 0`, exactly one item is moved from the free stack to the active set. `_activeCount` increments by 1, `freeHead` decrements by 1, and `freeHead + _activeCount === capacity` holds strictly at all times.
- **Exhaustion Guard**: When `freeHead === 0`, `acquire()` returns `null` safely without throwing an exception or allocating memory.

#### B. Swap-and-Pop Release Mechanics ($O(1)$)
```ts
public release(item: T): boolean {
  const itemIndex = this.itemToIndexMap.get(item);
  if (itemIndex === undefined) {
    return false; // Foreign object rejection
  }

  if (this.activeFlags[itemIndex] === 0) {
    return false; // Double-release guard
  }

  const slot = this.itemToActiveSlot[itemIndex];
  const lastSlot = --this._activeCount;

  if (slot !== lastSlot) {
    const swappedItemIndex = this.activeIndices[lastSlot];
    this.activeIndices[slot] = swappedItemIndex;
    this.itemToActiveSlot[swappedItemIndex] = slot;
  }

  this.activeIndices[lastSlot] = -1;
  this.itemToActiveSlot[itemIndex] = -1;
  this.freeIndices[this.freeHead++] = itemIndex;
  this.activeFlags[itemIndex] = 0;

  if (this.resetCallback) {
    try {
      this.resetCallback(item);
    } catch {
      // Guard against callback error corrupting pool state
    }
  } else if (item && typeof (item as unknown as IPoolable).reset === 'function') {
    try {
      (item as unknown as IPoolable).reset();
    } catch {
      // Guard against method error corrupting pool state
    }
  }

  return true;
}
```
- **Swap-and-Pop Correctness**: When releasing item at `slot`, the item at `lastSlot` is swapped into `slot`. The swapped item's reverse lookup `itemToActiveSlot[swappedItemIndex]` is updated to `slot`. The active array `activeIndices[0.._activeCount-1]` remains strictly dense and contiguous without holes.
- **Double-Release Guard**: If `activeFlags[itemIndex] === 0`, the release is rejected instantly. `_activeCount` is not decremented, `freeIndices` is not duplicated, and state corruption is physically prevented.
- **Foreign Object Rejection**: If `itemToIndexMap.get(item)` returns `undefined`, the object was not allocated by this pool. The method immediately returns `false` with 0 state alterations.

#### C. Dense Traversal Mechanics ($O(\text{activeCount})$)
```ts
public forEachActive(callback: (item: T, index: number) => void): void {
  const count = this._activeCount;
  for (let i = 0; i < count; i++) {
    const itemIndex = this.activeIndices[i];
    callback(this.storage[itemIndex], i);
  }
}
```
- Traversal iterates only over currently active items `[0 .. _activeCount - 1]`.
- No empty slots or inactive objects are evaluated, maximizing CPU L1 cache locality and minimizing iteration cycles.

### 2.4 `IPoolable` Interface & Contract Verification

#### Contract Definition
Added to `src/game/pooling/ObjectPool.ts`:
```ts
export interface IPoolable {
  reset(): void;
}
```

#### Dual-Mode Reset Execution Model
1. **Functional Reset (Options Callback)**: If `options.reset` is supplied, `options.reset(item)` is invoked upon release and upon `pool.reset()`.
2. **Object-Oriented Reset (`IPoolable` Method)**: If `options.reset` is omitted, `ObjectPool` detects whether `item` implements `IPoolable` (`typeof item.reset === 'function'`) and automatically executes `item.reset()`.
3. **Fault-Tolerant Exception Guarding**: Both paths are wrapped in try-catch guards, ensuring that buggy client reset logic cannot corrupt pool pointers, active counters, or free stacks.
